# NoteHub — Authentication, API Proxy и Protected Routes

## Цель работы

Расширить приложение **NoteHub** авторизацией пользователей и защищёнными маршрутами в Next.js App Router. Реализовать безопасное взаимодействие с внешним API через внутренние Route Handlers Next.js, работу с cookie-сессией, разделение API-кода для клиента и сервера, глобальное состояние авторизации и SSR/CSR-гидратацию данных заметок.

## Стек и принципы

- **Next.js App Router** — маршруты, серверные и клиентские компоненты, Route Handlers, параллельные и intercepting routes.
- **TypeScript** — типизация компонентов, API-функций, данных пользователя и заметок.
- **Axios** — единый HTTP-клиент для запросов.
- **Zustand** — глобальный store состояния авторизации.
- **TanStack Query / React Query** — запросы, мутации, кэширование, prefetch и hydration.
- **CSS Modules** — изолированная стилизация компонентов.
- **Vercel** — развёртывание приложения.
- **Cookies** — хранение и передача токенов авторизации.
- **Next.js Image** — оптимизированный вывод аватара с удалённого домена.

## Архитектура проекта

### Разделение API-слоёв

В проекте API-логика разделена по среде исполнения:

- `app/api/*` — серверный BFF/API proxy слой Next.js; принимает запросы от фронтенда и пересылает их на внешний backend.
- `lib/api/api.ts` — общий настроенный экземпляр Axios.
- `lib/api/clientApi.ts` — API-функции для client components.
- `lib/api/serverApi.ts` — API-функции для server components; передаёт cookies вручную через HTTP-заголовок `Cookie`.
- `types/note.ts` и `types/user.ts` — общие доменные типы.
- `lib/store/authStore.ts` — глобальное состояние пользователя и статуса авторизации.

### Поток авторизации

```text
Client Component
  ↓
lib/api/clientApi.ts
  ↓
Axios: /api/auth/*
  ↓
Next.js Route Handler: app/api/auth/*/route.ts
  ↓
External API: https://notehub-api.goit.study
  ↓
Set-Cookie / JSON response
  ↓
Browser cookies + Zustand auth store
```

Внешний backend хранит токены в cookie. Поэтому приложение использует `withCredentials: true`, а серверные функции отдельно получают cookies через `cookies()` и передают их в заголовках запросов.

## Итоговые архитектурные уроки

### API proxy / BFF

Внутренние Route Handlers `app/api/*` выступают Backend for Frontend: клиент не работает напрямую с внешним backend, а использует API текущего Next.js-приложения. Это помогает безопаснее работать с cookies, единообразно обрабатывать ошибки и убрать проблемы cross-origin взаимодействия.

### Разделение server и client API

- `clientApi.ts` применяется в интерактивных React-компонентах.
- `serverApi.ts` применяется в server components, layout и server-side логике.
- Server API обязан передавать cookie в headers вручную.
- Client API использует браузерные cookies через `withCredentials: true`.

### SSR и React Query hydration

Сервер получает данные через `prefetchQuery`, сериализует cache через `dehydrate`, затем клиент получает его через `HydrationBoundary`. Это улучшает начальную загрузку и предотвращает дублирование запросов.

### Auth state и server protection

Zustand отвечает за UI-состояние авторизации на клиенте, а `proxy.ts` — за фактическое ограничение доступа до рендера страницы. Нельзя использовать только Zustand для защиты private pages, потому что client state не является надёжной защитой маршрутов.
